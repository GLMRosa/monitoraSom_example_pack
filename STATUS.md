## ⚠ Read first — the vignettes run against the INSTALLED package

Every `.qmd` here opens with `library(monitoraSom)`, so rendering exercises
whatever is in your R library — **not** `R/refactored/`. When the installed
build lags the monorepo, the vignettes fail in ways that look like data or
authoring bugs and are neither.

This cost a debugging session on 2026-08-11. The installed build was from
**2026-07-21**, predating the FTM-108 fix (`47ebffa`, 2026-08-07) that gave
`template_name` a producer. Without it `fetch_template_metadata()` returns
`NA` for that column, `diagnostic_validations()` splits on it, and the split
yields empty groups — surfacing as:

```
All diagnostic validations failed.
Warning: diagnostic_validations: template 'NA' failed --
         Argument mu must be a nonempty numeric vector
```

Nothing in the pack was wrong. Before rendering, reinstall:

```sh
bash tools/refresh_cran_mirror.sh
R CMD build cran/monitoraSom && R CMD INSTALL monitoraSom_1.2.0.tar.gz
```

Note this sits in tension with the CLAUDE.md rule *"never `library(monitoraSom)`
when testing refactored code"*. That rule protects the **package** test suite,
which must exercise sources directly. These vignettes are the opposite case:
they document the user-facing experience, and the user has an installed package.
The rule to follow here is *keep the installed build current*, not *avoid it*.

## Decided

- Ship **only what cannot be recomputed**: raw audio, recorder sidecars, and the
  manual ROI segmentation. No `.rda`. No metadata store, no template cuts —
  those are what the vignettes teach you to produce.
- `bcu_recordings` + `bcu_soundscapes` are **one example with two roles**:
  `recordings/` are the focal recordings the templates came from,
  `soundscapes/` the search space matching runs against.
- **SM4 keeps its native card layout** — `*_Summary.txt` one level above a
  `Data/` subdirectory — so it matches a real recorder card. The summary is the
  source of lat/lon, temperature and battery; it is not decoration.
- Stored paths are **dataset-relative**, matching the convention in the
  package's own `df_rois` and making each dataset a drop-in `project_path`.
- Intentional defects **stay**: the 44-byte AudioMoth header and the three
  zero-byte SM4 files are fixtures, not faults.
- One vignette per dataset, living **inside** the dataset, so it travels with
  the data it needs.
- Manifest criterion: **anything not regenerable is a member.** That is why the
  `.qmd` files are manifested — authored prose cannot be rebuilt.

### 2. Malformed-data revision — ✅ ADDRESSED 2026-08-10 (in the vignettes)

**Decision:** the fixtures stay untouched. What was missing was not a fix to the
files but a **treatment in the documentation**, and every vignette now carries
one, in a `## Handling malformed recordings` section right after *Reading the
inputs*.

The content rests on a fact worth stating plainly, verified by execution rather
than assumed: **recordings fail in two ways, and neither check catches both.**

| Mode | What happens | Where it shows | Dataset |
|---|---|---|---|
| **Hard** | the reader cannot open the file at all | `metadata_errors` table, never in `df_soundscapes` | `sm4`, 3 zero-byte files, message `non-conformable arguments` |
| **Soft** | the file opens and carries no audio | an ordinary looking row, betrayed only by `soundscape_duration == 0` | `audiomoth`, the 44-byte truncated header, at a plausible 48 kHz |

Measured on 2026-08-10: `sm4` returns 12 valid rows and 3 errors with zero
soft failures; `audiomoth` returns 16 valid rows, **zero** errors and one
soft failure; `bcu` is clean on both counts.

The soft mode is the dangerous one. Nothing is logged, so an empty recording
enters `fetch_match_grid()` as a real pair, `run_matching()` scores it and finds
nothing, and the result reads as *"the template missed everything here"* rather
than *"there was no audio"*. Recall is diluted with no error to warn you.

Each vignette therefore runs **both** checks and then filters, and everything
downstream consumes `df_usable`:

```r
df_usable <- df_soundscapes |> filter(soundscape_duration > 0)
```

That filter is the idiom already used by the W3 segmentation driver, not a new
invention. `metadata_errors` has no public accessor, so the vignettes read it
through `DBI::dbReadTable()` on the store.

Per dataset the section is angled at what that corpus teaches: `sm4` gets the
hard mode plus a note that filtering keeps *"unreadable"* and *"nothing there"*
distinct in exported annotations (Option C); `audiomoth` gets the soft mode and
the warning above; `bcu` runs both checks green, as the baseline a reader needs
in order to recognise an unhealthy corpus.

All three sections were executed against the real stores before being written,
and all three `.qmd` render clean under Quarto 1.9.36.

## How to resume

The builder is `R/sandbox/build_example_pack.R` in the monorepo (it is not part
of the pack, so it would ship inside the tarball if it were).

```r
source("R/sandbox/build_example_pack.R")

ep_status()             # per-dataset counts vs expectation
ep_build()              # idempotent; ep_build(force = TRUE) rebuilds the stores
ep_verify()             # structural invariants
ep_recompute_check()    # proves the pack regenerates what it omits
ep_tar()                # tarball + top-level-member assertion
```

Keep the directory clean: `ep_recompute_check()` works in a temporary copy and
removes it, so running the checks leaves no by-products. If you run the vignette
chunks in place, they *will* create `soundscapes_metadata.duckdb` and
`roi_cuts/` — delete those afterwards, or the manifest check will flag them.
